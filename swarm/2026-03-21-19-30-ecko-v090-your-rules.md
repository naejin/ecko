## Consensus

# Consensus: v0.9.0 "Your Rules" — configurable ruff rules, runner decomposition, bug fix, and ledger housekeeping

## Recommendation

### Theme: "Your Rules"

Ecko has spent five releases building a solid detection-echo-correction loop. v0.9.0 lets users bring their own lint standards into that loop, starting with ruff. Scope is deliberately narrow: four deliverables, one bug fix, and one small enhancement.

### Deliverables

#### 1. Extra ruff rules (`ruff_extra_rules`) — Priority: P0

**What:** A flat string list in `ecko.yaml` that appends additional ruff rule codes to ecko's built-in `--select`. Unmapped codes get lowercased as their check name (e.g., `C901` becomes `c901`).

**Config:**
```yaml
ruff_extra_rules:
  - C901     # complexity
  - N801     # class naming
  - SIM101   # simplification
```

**Files to modify:**

- `checks/config.py`
  - Add `"ruff_extra_rules"` to `_KNOWN_KEYS`
  - Add `get_ruff_extra_rules(config) -> list[str]` — returns list of rule code strings; validates each matches `^[A-Z]+[0-9]+$`, logs warning and skips invalid codes
  - ~20 lines

- `checks/tools/ruff_adapter.py`
  - Accept optional `extra_rules: list[str] = None` parameter in `run_ruff()`
  - Build `--select` string: `RUFF_RULES + "," + ",".join(extra_rules)` when extras present
  - Unmapped codes: `RULE_MAP.get(code, code.lower())` (line 78 already does this — no change needed for mapping)
  - ~10 lines changed

- `checks/runner.py`
  - Import `get_ruff_extra_rules` from config
  - Compute `extra_rules` once before file loops (both `run_post_tool_use` and `run_stop` per-file sweep)
  - Pass `extra_rules=extra_rules` to `_run_layer2_checks`, which passes to `run_ruff()`
  - Add `extra_rules: list[str] | None = None` parameter to `_run_layer2_checks`
  - ~20 lines

- `ecko.yaml.example`
  - Add documented `ruff_extra_rules` section with examples
  - ~10 lines

**Total: ~60 lines across 4 files.**

#### 2. Runner decomposition — Priority: P1

**What:** Extract two self-contained modules from `runner.py`.

**New files:**

- `checks/bash_guard.py` (~80 lines)
  - Move: `check_bash_command()`, `run_pre_tool_use_bash()`, `_rm_prefix`, all hardcoded pattern dicts
  - Imports: `checks.config`, `checks.regex_utils`, `checks.result`

- `checks/git.py` (~60 lines)
  - Move: `_get_modified_files()`, `_normalize_path()`
  - Imports: `os`, `subprocess`

**Modify:**

- `checks/runner.py`
  - Replace moved functions with imports from new modules
  - Keep re-exports for backward compatibility
  - Runner drops from 737 to ~600 lines

**Total: ~140 lines new, ~140 lines removed from runner.**

#### 3. Bug fix: `_get_modified_files` hardcoded `4h` — Priority: P0

**What:** Line 683 of `runner.py` has `--since=4h` hardcoded. Should use `session_hours` config value.

**Fix in `checks/git.py` (after decomposition):**
- `_get_modified_files(cwd, session_hours=4.0)` — add parameter
- Caller in `run_stop()` passes `get_session_hours(config)`
- Format as `f"--since={int(session_hours)}h"`

**~5 lines changed.**

#### 4. Ledger pruning — Priority: P2

**What:** Prune-on-read: when `read_session()` finds >50% stale entries and the file exceeds 50KB, rewrite with only active entries. Atomic via temp file + `os.replace()`.

**File:** `checks/ledger.py`
- After `_read_raw()`, count total vs active entries
- If `total > 0 and active / total < 0.5 and file_size > 50_000`: rewrite
- Temp file (`ledger.jsonl.tmp`), then `os.replace()` for atomicity
- All inside try/except — pruning failure never blocks

**~25 lines added.**

#### 5. Per-tool timing (debug mode) — Priority: P2

**What:** Layer 3 tool timing in debug output.

**File:** `checks/runner.py` (in `run_stop` ThreadPoolExecutor block)
- Record `time.monotonic()` around each future result
- `debug(f"layer3: {tool_name} completed in {elapsed:.1f}s")`

**~10 lines.**

### NOT in v0.9.0

| Feature | Reasoning |
|---|---|
| `biome_use_project_config` | Ship ruff first. Get user feedback, then design biome configurability informed by that experience. Biome's config story (JSON, camelCase rules) is more complex than ruff's (flat code list). |
| `ruff_use_project_config` | Undermines ecko's value prop. If users want full ruff, run ruff directly. Ecko's value is curated rules in the echo-correction loop. |
| `ruff_disabled_rules` | `disabled_checks` already lets users suppress by ecko check name. Two disable mechanisms creates confusion. |
| Severity levels | Claude Code's hook protocol has exit 0/1/2. No graduated response. Severity would be cosmetic-only. |
| Structured JSON output | No consumer exists. Build when something needs it. |
| Go/Rust support | New language = new adapters, custom checks, validation. Full milestone on its own. |
| `/ecko:session` command | Session ledger is one release old. Let data model prove itself before building dashboards. |
| Session stats in stop output | Same reasoning. Self-correction line is sufficient for now. |
| Dry-run mode | `ECKO_DEBUG=1` covers the use case. |
| `filtering.py` extraction | `filter_suppressed` and `is_excluded` are small, tightly coupled to runner's per-file flow. Not worth a separate module yet. |
| Biome extra rules via temp config merge | Biome uses JSON config, not CLI flags. Merging configs is fragile (rule groups, temp files, concurrency). |

## Key Agreements

1. **Theme is "Your Rules"** — all four syntheses independently arrived at this name.
2. **`ruff_extra_rules` is the headline feature** — universal agreement on design: flat string list, appended to `--select`, unmapped codes lowercased.
3. **Runner decomposition is overdue** — all four agree on `bash_guard.py` and `git.py` extraction.
4. **The hardcoded `4h` is a real bug** — all four confirmed line 683. Trivial fix.
5. **Severity levels, JSON output, Go/Rust are NOT in v0.9.0** — universal exclusion.
6. **`ruff_disabled_rules` and `ruff_use_project_config` are NOT in v0.9.0** — additive model (extra rules only) is the right first step.

## Resolved Trade-offs

**Biome configurability (Synths 1, 3, 4 include; Synth 2 excludes):**
Excluded. Ship ruff first, get user feedback, then design biome informed by experience. Biome's JSON config is fundamentally more complex than ruff's CLI flags.

**`/ecko:session` command (Synths 1, 4 include; Synths 2, 3 exclude):**
Excluded. Session ledger is one release old. Let data model prove itself.

**Ledger pruning (Synths 1, 2, 3 include; Synth 4 excludes):**
Included. Any append-only file without bounds is a latent issue. The fix is ~25 lines with zero risk. Dual-condition trigger (>50% stale AND >50KB) avoids unnecessary rewrites.

**Decomposition scope (2 vs 3 modules):**
Two modules. `filtering.py` extraction adds import complexity for small functions tightly coupled to runner flow. `bash_guard.py` and `git.py` are clean, self-contained boundaries.

**Per-tool timing (Synths 2, 3 include visible; Synths 1, 4 exclude):**
Included but debug-mode only. ~10 lines, zero risk, complements observability.

## Open Questions

1. **Ruff rule code validation regex** — `^[A-Z]+[0-9]+$` may not cover all valid ruff codes (e.g., prefix-only like `UP`). Verify against ruff's actual code format.
2. **Ledger pruning concurrency** — two hooks pruning simultaneously is safe (`os.replace` is atomic) but untested on Windows with Python 3.10.
3. **`ruff_extra_rules` + `disabled_checks` interaction** — if user adds `C901` to extra rules and `c901` to disabled_checks, echo is generated then filtered. Consistent but potentially confusing. Document.
4. **Future biome design** — should v0.10.0 mirror the ruff model (`biome_extra_rules`) or use `biome_use_project_config`? The ruff experience will inform this.
